# Requirements Document

## Introduction

Система уведомлений о продажах товаров по цене ниже минимальной предназначена для автоматического мониторинга и оповещения о случаях, когда товар был продан на любом из аккаунтов по цене, которая ниже установленной минимальной цены для данного товара. Система интегрируется в существующий процесс обработки pending stock operations и отправляет уведомления в главный Telegram чат при обнаружении таких случаев.

## Requirements

### Requirement 1

**User Story:** Как администратор системы, я хочу получать уведомления о продажах товаров по цене ниже минимальной, чтобы оперативно реагировать на потенциальные убытки и корректировать ценовую политику.

#### Acceptance Criteria

1. WHEN товар продается по цене ниже установленной минимальной цены THEN система SHALL отправить уведомление в главный Telegram чат
2. WHEN минимальная цена для товара установлена в 0 или отсутствует THEN система SHALL пропустить проверку для данного товара
3. WHEN обрабатывается pending stock operation с несколькими позициями THEN система SHALL проверить каждую позицию отдельно
4. WHEN уведомление отправляется THEN оно SHALL содержать информацию об аккаунте, товаре (SKU), цене продажи и минимальной цене

### Requirement 2

**User Story:** Как разработчик системы, я хочу интегрировать проверку цен в существующий процесс обработки операций, чтобы не создавать дополнительную нагрузку на систему и обеспечить своевременность уведомлений.

#### Acceptance Criteria

1. WHEN система обрабатывает pending stock operation типа DEDUCTION THEN она SHALL выполнить проверку цен для всех позиций заказа
2. WHEN проверка цен выполняется THEN она SHALL использовать существующий PricesService для получения минимальных цен
3. WHEN проверка цен завершается THEN основной процесс обработки операции SHALL продолжиться независимо от результата проверки
4. IF проверка цен вызывает ошибку THEN система SHALL логировать ошибку и продолжить обработку операции

### Requirement 3

**User Story:** Как пользователь системы, я хочу получать структурированные и информативные уведомления, чтобы быстро понимать суть проблемы и принимать соответствующие меры.

#### Acceptance Criteria

1. WHEN формируется уведомление THEN оно SHALL содержать название аккаунта, SKU товара, цену продажи и минимальную цену
2. WHEN уведомление отправляется THEN оно SHALL использовать существующий формат уведомлений StockSyncNotificationService
3. WHEN в заказе несколько позиций с нарушением цены THEN система SHALL отправить одно сводное уведомление для всего заказа
4. WHEN уведомление формируется THEN оно SHALL включать ссылку на детали операции, если доступен BASE_URL

### Requirement 4

**User Story:** Как администратор системы, я хочу иметь возможность настраивать поведение системы уведомлений, чтобы адаптировать её под изменяющиеся бизнес-требования.

#### Acceptance Criteria

1. WHEN система инициализируется THEN она SHALL использовать существующую конфигурацию Telegram чатов из stock_sync_config
2. WHEN происходит ошибка получения цены товара THEN система SHALL логировать предупреждение и пропустить проверку для данного товара
3. WHEN PricesService недоступен THEN система SHALL логировать ошибку и пропустить все проверки цен
4. IF система не может отправить уведомление THEN она SHALL использовать существующую очередь отложенных сообщений

### Requirement 5

**User Story:** Как разработчик системы, я хочу обеспечить надежность и производительность новой функциональности, чтобы она не влияла негативно на основные процессы системы.

#### Acceptance Criteria

1. WHEN выполняется проверка цен THEN она SHALL выполняться асинхронно и не блокировать основной процесс
2. WHEN происходит ошибка в процессе проверки цен THEN основная логика обработки операции SHALL продолжить работу
3. WHEN система обрабатывает большое количество операций THEN проверка цен SHALL выполняться эффективно без значительного увеличения времени обработки
4. WHEN система логирует события проверки цен THEN она SHALL использовать существующий standardized_logger для консистентности
