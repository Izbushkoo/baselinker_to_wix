# Требования к улучшению отчетов склада

## Введение

Данная функциональность расширяет существующие отчеты склада добавлением информации о дате первого публикования офферт на Allegro. Система будет хранить эти данные в поле базы данных товара и обновлять их через периодическую задачу и ручной эндпоинт с использованием батчевых запросов к микросервисным API.

## Требования

### Требование 1

**Пользовательская история:** Как пользователь системы, я хочу видеть дату первого публикования офферты в отчетах склада, чтобы анализировать жизненный цикл товаров на площадке.

#### Критерии приемки

1. КОГДА пользователь запрашивает отчет склада ТОГДА система ДОЛЖНА включить колонку "Дата первой публикации"
2. ЕСЛИ у товара есть офферты на Allegro ТОГДА система ДОЛЖНА отобразить самую раннюю дату публикации среди всех офферт
3. ЕСЛИ у товара нет офферт на Allegro ТОГДА система ДОЛЖНА отобразить пустое значение или "Не опубликован"
4. КОГДА система получает данные об офертах ТОГДА она ДОЛЖНА использовать батчевые запросы до 100 SKU за раз

### Требование 2

**Пользовательская история:** Как администратор системы, я хочу иметь периодическое обновление данных о публикации офферт, чтобы информация в отчетах была актуальной.

#### Критерии приемки

1. КОГДА система запускает еженедельную задачу ТОГДА она ДОЛЖНА обновить данные о публикации для всех товаров в базе
2. КОГДА выполняется обновление данных ТОГДА система ДОЛЖНА использовать батчевые запросы по 100 SKU
3. КОГДА обновление завершается ТОГДА система ДОЛЖНА логировать количество обновленных товаров
4. ЕСЛИ происходит ошибка при обновлении ТОГДА система ДОЛЖНА продолжить обработку остальных товаров

### Требование 3

**Пользовательская история:** Как администратор системы, я хочу иметь возможность запустить обновление данных о публикации вручную, чтобы получить актуальную информацию по требованию.

#### Критерии приемки

1. КОГДА администратор вызывает ручной эндпоинт ТОГДА система ДОЛЖНА запустить обновление данных о публикации
2. КОГДА запускается ручное обновление ТОГДА система ДОЛЖНА вернуть статус операции и количество товаров для обработки
3. КОГДА выполняется ручное обновление ТОГДА система ДОЛЖНА обработать все товары или указанный список SKU
4. ЕСЛИ ручное обновление уже выполняется ТОГДА система ДОЛЖНА вернуть ошибку о том, что операция уже в процессе

### Требование 4

**Пользовательская история:** Как администратор системы, я хочу контролировать нагрузку на микросервисы, чтобы не перегружать внешние API.

#### Критерии приемки

1. КОГДА система делает запросы к микросервису ТОГДА она ДОЛЖНА соблюдать лимиты rate limiting
2. КОГДА происходит ошибка API ТОГДА система ДОЛЖНА реализовать exponential backoff для повторных попыток
3. КОГДА система обрабатывает товары батчами ТОГДА она ДОЛЖНА добавлять задержки между запросами
4. ЕСЛИ микросервис недоступен ТОГДА система ДОЛЖНА пропустить обновление и продолжить с остальными товарами

### Требование 5

**Пользовательская история:** Как пользователь системы, я хочу получать отчеты в том же формате, что и раньше, но с дополнительной информацией, чтобы не нарушать существующие процессы.

#### Критерии приемки

1. КОГДА генерируется отчет ТОГДА все существующие колонки ДОЛЖНЫ остаться без изменений
2. КОГДА добавляется новая колонка ТОГДА она ДОЛЖНА располагаться после колонки "URL изображения"
3. КОГДА экспортируется Excel файл ТОГДА новая колонка ДОЛЖНА иметь правильное форматирование даты
4. КОГДА пользователь выбирает экспорт без изображений ТОГДА новая колонка ДОЛЖНА присутствовать в обоих вариантах отчета

### Требование 6

**Пользовательская история:** Как разработчик системы, я хочу хранить данные о датах публикации в базе данных, чтобы они были доступны мгновенно при генерации отчетов.

#### Критерии приемки

1. КОГДА система получает данные о дате публикации ТОГДА она ДОЛЖНА сохранить их в поле товара в базе данных
2. КОГДА генерируется отчет ТОГДА система ДОЛЖНА использовать сохраненные в базе данные без дополнительных API запросов
3. КОГДА обновляются данные о публикации ТОГДА система ДОЛЖНА перезаписать существующие значения в базе
4. ЕСЛИ у товара нет данных о публикации в базе ТОГДА система ДОЛЖНА получить их точечно через API во время генерации отчета
